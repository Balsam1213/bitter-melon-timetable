# 2026-10-25 开发日志

## 今日成果：v1.1「节假日日历与调休提醒」

### 背景

v1.0 只有「节假日不提醒」，且 holiday-cn 同步时把调休上班日（`isOffDay=false`）直接丢弃，整个数据模型没有「调休」概念；提醒按自然星期匹配课程，调休周六无法按「上周四的课」提醒。用户确认需求：调休日按指定周几上课（默认按当天）、节假日管理改为日历形式。

### 关键设计决策

1. **存储沿用差集模式**：放假与调休各走一套「官方 ∪ 手动添加 − 手动删除」，同步只重写官方集合 → 手动改动天然不被覆盖，与 v1.0 语义完全兼容。新增 DataStore key：`makeup_official / makeup_added / makeup_removed / makeup_weekdays`（元素 `yyyy-MM-dd=4` 表示按周四）。
2. **「按周几」映射只能用户设置**：holiday-cn 只给日期不给按周几，同步只标日期；`makeup_weekdays` 永不被同步触碰。UI 上点调休日期时用 chips 引导选择。
3. **调休不受「节假日不提醒」开关控制**：放假跳过提醒看开关；调休改的是「按哪天的课表」，属于日历事实。
4. **放假优先于调休**：同一日期两种标记冲突时 `effective()` 求差时放假日从调休集合剔除，避免歧义。
5. **簿记逻辑做成纯函数**（`HolidayLogic.setDayStatus` 等）供 Repository 复用并被单测覆盖——这是本版唯一的数据正确性风险点。

### 遇到的问题

- **星期编号约定踩坑**：java.time 周一=1..周日=7，周六是 6 不是 7。项目代码全用正确约定，我单测预期写错被测试抓住——单测第一天就值回票价。
- `EffectiveDayOfWeek` 初版没校验日期是否真在调休集合里，残留映射会错误改写普通日；改为先查 `makeupDays` 再取映射，并补了单测用例。
- 模拟器 ABI：构建产物按 ABI 拆分，x86_64 模拟器要装 `app-universal-debug.apk`（或对应 x86_64 包）。

### 验证

- `assembleDebug` + `testDebugUnitTest` 23 个全绿
